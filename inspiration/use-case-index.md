# Inspiration by Use Case

## 1. What is it?

The routing table for inspiration: 25 project and section types, each mapped to the directories to browse and the specific reference entries in the collection that apply. It exists so an agent building a specific thing starts from the right reference set in minutes — not from a general gallery wander ([directories.md](directories.md) is the catalogue; this file is the router).

## 2. How to read it

Each row names the **first stops** (directories to browse, with the filter to use) and **collection entries** (structured references in [websites/](websites/website-index.md) worth reading first). The knowledge files named in the last column are where the extracted patterns go ([patterns.md](patterns.md) carries the section-level patterns).

## 4. Practical workflow

1. **Find your row** (or the nearest two — most projects are hybrids: a SaaS landing *plus* an editorial blog).
2. **Read the collection entries first** — structured analyses are faster than browsing.
3. **Browse the directories with the named filters** for breadth; timebox (5–8 references).
4. **Extract patterns via [patterns.md](patterns.md)** and record the direction in the project's plan ([../skills/frontend-design/SKILL.md](../skills/frontend-design/SKILL.md) phase 3).
5. **Contribute anything exceptional** back into the collection ([contributing.md](contributing.md)).

## 5. Common mistakes

- **Only one row consulted** — hybrids need their second row; a SaaS landing with heavy editorial content needs both rows' references.
- **Frontier references for practical surfaces** — Igloo-class immersion applied to a checkout; the fit filter is [../visual-styles/interface-styles.md](../visual-styles/interface-styles.md) §6.
- **Skipping the collection for raw browsing** — the entries encode the "why it works"; browsing alone does not.
