# Website Reference Collection

## 1. What is this?

The collection of *individual websites worth structured study* — not a list of links, but a set of analysis entries that record what a site does, why it works, and what an agent can learn from it without copying it. Each entry follows the standard template (§4) so comparison is possible, and the collection is indexed for retrieval ([website-index.md](website-index.md)).

## 2. Why entries, not links?

A link teaches nothing; an entry that names the typography, the colour behaviour, the section logic and the motion strategy converts one excellent site into transferable knowledge. It also compounds: patterns extracted across entries ([../patterns.md](../patterns.md)) and styles named across entries ([../../visual-styles/README.md](../../visual-styles/README.md)) turn the collection into a design vocabulary an agent can reason with.

## 3. How to use the collection

1. **Route from the use-case index** ([../use-case-index.md](../use-case-index.md)) to the relevant entries.
2. **Read the entry, then the live site** — entries describe design direction and are dated; sites change. The entry's *what to verify live* field names what to check on arrival.
3. **Extract with the anti-copying rules** — [../contributing.md](../contributing.md) §6 governs translation: study the *why*, build your own *what*.
4. **Contribute** — the collection grows through project work ([../contributing.md](../contributing.md)).

## 4. The entry template

Every entry contains, in this order:

1. **Identity** — name, URL, category, industry, access date.
2. **Why it is worth studying** — the one-paragraph case for the entry.
3. **Visual direction** — the overall aesthetic position (style vocabulary used).
4. **Typography** — faces, hierarchy behaviour, distinctive type moves.
5. **Colour system** — palette logic, semantic/accent behaviour, theme.
6. **Composition and layout** — grid, density, section rhythm.
7. **Navigation** — structure and any unconventional moves.
8. **Interesting sections** — the sections worth studying specifically.
9. **Interaction and motion** — the motion strategy and its hierarchy.
10. **Imagery and visual assets** — the image/asset approach.
11. **Distinctive details** — the small moves that carry craft.
12. **What makes it effective** — the effect-on-user case.
13. **What to learn (and what to leave)** — transferable lessons; the explicitly non-transferable parts.
14. **Suitable project types** — where this reference genuinely applies.
15. **Related references and patterns** — collection cross-links.
16. **What to verify live** — the volatile specifics to check on arrival.

## 5. Provenance discipline

Entries are written from documented professional knowledge of these well-known sites (public launches, press coverage, long-standing design discussion) with the access date recorded — they are `[canonical]`-grade descriptions under the library's tag rules ([../../README.md](../../README.md) §H): no invented technical specifics, no invented metrics, no claims about exact stack unless verified in the entry's sources. **Before any build decision relies on a specific detail, verify it live** — each entry names what to check. Where an entry's facts came from a fetched source, the source is cited in the entry's References section.

## 7. Extending the collection

The contribution workflow ([../contributing.md](../contributing.md)): evaluate worth, categorise, inspect (browser automation where available — screenshots stored only where legally appropriate), write the entry in the template above, update the index, commit with the standard message. The collection privileges quality and diversity over count.
